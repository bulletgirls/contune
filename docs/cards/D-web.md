# D. 화면

세션 4(사람 2). 빌드 단계 없는 vanilla JS(ES 모듈)와 저장소에 들어 있는 uPlot으로, **계약(02 §6 응답 형식)만 보고** 먼저 만든다. `?mock=1`이면 브라우저 안의 mock이 같은 형식으로 답하므로 백엔드 없이 09:50부터 시작할 수 있다. **개념: 한 화면 관제, 실행 ID 연결, 함수 단위 추적(구간 비교).**

공통 설계 근거: 02 §6(응답 형식), §12(화면 설계: 트리, 열지도, 업무 패널, 배치판, 플로우 그래프, 타임머신 띠 5개, A·B 구간), 기획서 8~11쪽 화면 시안.

**화면 공통 규칙**
- 파일은 `internal/manager/web/static/` 아래에만 둔다. Go 코드는 K1의 `web.go` 하나뿐이다.
- 외부 CDN·폰트·라이브러리 금지(폐쇄망). 그래프 라이브러리는 uPlot만 쓰고 플로우 그래프·플레임 그래프·열지도는 SVG나 DOM으로 직접 그린다.
- **색은 하는 일로 정한다.**
  - 상태 색(정상·주의·위험·무응답, 성공·실패·실행 중·대기·조건 대기)은 상태에만 쓰고, 항상 글자나 기호와 함께 쓴다(색만으로 구분하지 않음).
  - CPU 열지도는 **한 색상의 진하기**(옅음 → 짙음)로만 그린다.
  - 시계열의 계열 색은 상태 색과 겹치지 않는 범주 색을 정해진 순서로 쓴다.
  - 값·라벨 글자는 본문 글자색을 쓴다.
- **한 차트에 축은 하나.** 단위가 다르면 띠를 나눈다(02 §12.2).
- 색 토큰은 `:root`에 두고 `@media (prefers-color-scheme: dark)`에서 다시 정의한다.
- 기준 폭은 1280px이다. 900px 아래에서는 트리를 접는다.
- 주기 갱신은 `document.hidden`이면 멈춘다. 요청이 실패하면 화면 위에 작은 경고 띠를 띄우고 다음 주기에 다시 시도한다.
- `localStorage`는 트리 접힘 같은 편의에만 쓰고 `try/catch`로 감싼다.

### 만들 것
1. **골격**(`index.html`, `style.css`)
   - 위 막대: 로고 "이음", 메뉴 **대시보드 · 서버 · 배치판 · 실행 이력**, 오른쪽에 `HH:MM:SS · 2초마다 갱신`.
   - 왼쪽: 트리. 오른쪽: 본문.
   - 색 토큰은 배경·면·글자 3단계·선·상태 색·CPU 단계 4개·계열 색 4개다.
2. **라우터**(`app.js`): 해시 주소를 화면 함수에 연결한다. 이 카드에서는 `#dashboard`(기본), `#hosts`, `#host/<id>`, `#board/<경로>[/<flow-id>]`, `#runs`, `#run/<exec_id>`의 자리만 만들고 내용은 각 카드가 채운다.
   - `#board/` 뒤 경로가 배치판 경로와 같으면 목록이고, 아니면 마지막 마디를 플로우 ID로 읽는다(02 §12.1).
   - 트리에서 고른 범위는 `?g=<그룹 경로>`로 주소에 남긴다.
3. **`api.js`**
   - `api(path, opts)`: 주소에 `?mock=1`(또는 `localStorage.mock = 1`)이면 `mock.handle(path, opts)`, 아니면 `fetch('/api/v1' + path)`. JSON 파싱과 에러 처리를 여기서 한다.
   - `poll(fn, ms)`: 주기 갱신 도우미. 페이지를 떠나면 멈춘다.
4. **`mock.js`**: 02 §6 응답 형식을 그대로 돌려주는 **결정적 생성기**(고정 seed). 모든 화면이 이것만으로 동작해야 한다.
   - `/hosts`
     - 서버 43대이고 그룹은 02 §13 `fleet.yaml`의 8개 + 실제 3대다.
     - `ext-04`는 silent, `dw-02`는 crit(메모리 93)이다.
     - 폭주 구간(아래)에는 `match-01`이 warn이다.
   - `/flows`
     - 플로우 39개, 배치판 6개다(개장준비 6, 장중 5, 정산 7, 대외송수신 9, 정보계적재 8, 주간월간 4).
     - `market-open`은 02 §9 모양이다. 깊이 0~3이고, `load-equity`는 attempt 2, `start-matching`은 `procs: 1`이다.
     - `대외송수신/ext-send-margin`은 FAILED(attempt 3)다.
   - `/runs`, `/runs/{id}`: 위와 맞는 실행·이벤트·`log_tail`.
   - `/series`
     - 시각 기반 사인파 + 잡음이다.
     - `start-matching` 실행의 `biz.order.*`·`job.cpu.pct`는 **폭주 구간**을 담는다. 폭주 구간은 "지금 − 4분 ~ 지금 − 1분"이고, 이때 접수 1500 → 6000, 처리 정체, 대기·p99 급등, CPU 100이다.
   - `/panels`: 02 §12.1 체결 패널. 폭주 중 값은 기획서 8쪽(6,000 / 5,860 / 2,240 / 385ms / 0.6%)과 같다.
   - `/profile`: `from`~`to`가 폭주 구간과 겹치면 B 모양(`book_insert` 약 63%), 아니면 A 모양(`check_risk` 34, `price_cross` 22, `book_insert` 15, `expire_orders` 11)이다. 스택은 `matching_svc;main;handle_order;…` 꼴이다.
   - `POST /flows/{id}/run`은 201, 실행 중이면 409다.
5. **트리**(`tree.js`)
   - 뿌리는 둘이다. `서버`(그룹 경로를 `/`로 나눈 단계 → 서버)와 `배치판`(배치판 경로 → 플로우).
   - 노드마다 하위의 가장 나쁜 상태와 개수를 붙인다(예: "주의 2", "실패 1").
     - 서버 상태의 나쁜 순서: crit > silent > warn > ok
     - 플로우 상태의 나쁜 순서: FAILED > RUNNING > 예정 > SUCCEEDED
   - 접고 펴기 상태는 `localStorage`에 둔다. 노드를 고르면 범위를 주소에 남기고 본문을 다시 그린다. 서버를 고르면 `#host/<id>`, 플로우를 고르면 `#board/<경로>/<id>`로 간다.
   - 트리는 `/hosts`·`/flows`를 5초마다 다시 읽는다.
6. **임시 대시보드**(`dash.js`): uPlot 차트 1개로 `/series?name=host.cpu.pct`(최근 5분)를 2초마다 그린다. G0 확인용이고 D4가 바꾼다.

### 테스트 (미룸 가능 → 수동 확인)
- `?mock=1`: 트리에 서버 43대·그룹 8개(상위 4개)와 플로우 39개·배치판 6개가 뜬다. 집계가 mock 상태와 맞는다(배치판 `대외송수신 · 실패 1`, 서버 `대외정보 · 위험 1 · 무응답 1`(dw-02, ext-04), 그 아래 `정보계 · 위험 1`, `대외연계 · 무응답 1`).
- 실제 API(`eum dev`): 임시 차트가 움직인다.
- 콘솔 에러가 없다. 다크 모드에서 글자가 읽힌다.

위 수동 확인 3개. 완료 보고에 "D2~D6가 쓸 모듈과 함수" 목록.

## D2. 플로우 그래프 · 배치판 · 실행 이력 [하]

| 항목 | 내용 |
|---|---|
| 세션 · 시각 | 세션 4 · 10:45–11:35 |

### 만들 것
1. **배치판 목록** `#board/<경로>`: 플로우 표(이름, 최근 상태, 다음 실행, 최근 소요, 마지막 실행 시각). 줄을 누르면 `#board/<경로>/<id>`.
2. **플로우 그래프** `#board/<경로>/<id>` (기획서 9쪽)
   - 머리:
     - 경로 `배치판 › 개장준비 › market-open`
     - 일정 글(`평일 05:30`), 다음 실행, 최근 상태와 시각
     - **지금 실행** 버튼: `POST /flows/{id}/run`. 409면 "이전 실행이 진행 중입니다" 알림.
   - SVG 배치:
     - 스텝을 `level`별 열로 놓는다. 열 머리에 `단계 0`, `단계 1 · 병렬`(열에 2개 이상), `단계 2 · 합류`(선행 2개 이상인 스텝이 있음)를 단다.
     - 같은 열에서는 YAML 순서로 세로 배치한다.
     - 위쪽에 호스트 띠 이름을 적는다(`batch-01`, `match-01`).
   - 노드:
     - 사각형 왼쪽에 상태 색 막대를 둔다.
     - 스텝 id(고정폭 글꼴), 경과 시간, 호스트, 상태 점을 넣는다.
     - attempt ≥ 2면 배지 `재시도 N회차`, RUNNING이면 은은한 깜박임이다.
     - `procs > 0`이면 아래에 `서비스 실행 중 · <exec_id 앞 6자>…` 꼬리표를 붙인다.
   - 선:
     - 선행 오른쪽 → 후행 왼쪽 곡선 화살표.
     - **서버를 넘는 선**(호스트가 다름)은 다른 색으로 그리고 "서버를 넘어 실행" 라벨을 단다.
     - 선행 실패로 막힌 WAITING 노드는 회색 점선 테두리와 "선행 실패로 대기"로 표시한다.
   - 1초마다 `/flows?board=<경로>`를 다시 읽는다. 노드를 누르면 그 스텝 최신 attempt의 `#run/<exec_id>`로 간다.
   - 아래에 최근 실행 표(`/runs?flow=<id>&limit=30`): 시각, 스텝, 호스트, attempt, 상태, 소요, 실행 방식.
   - 폭 1280에서 깊이 5단계까지 가로 스크롤 없이 들어간다.
3. **실행 이력** `#runs`: 표(시각, 플로우, 스텝, 호스트, attempt, 상태, 소요, 종료 코드)와 플로우·호스트·상태 거르기. 줄을 누르면 `#run/<exec_id>`. `/runs?…&limit=200`.

### 테스트 (미룸 가능 → 수동 확인)
- mock의 `market-open`이 열 4개(0·1·2·3)이고, 단계 1 머리가 `병렬`, 단계 2 머리가 `합류`다. `load-equity`에 `재시도 2회차`, `start-matching`에 `서비스 실행 중`이 보인다.
- `ext-send-margin` 그래프가 FAILED이고 `재시도 3회차`다.
- 실제 API(B5 이후): `hello`를 지금 실행하면 노드 색이 바뀐다.

### 완료 기준
위 확인. 폭 1280 스크린샷 1장을 완료 보고에 붙임(발표 자료용).

| 항목 | 내용 |

| 넘겨주는 것 | `renderFlame`, `compareLeaf`, `renderTopTable` → D5, X2 |

### 만들 것
- `renderFlame(el, {stacks, title, subtitle, highlight})`
  - 접힌 스택으로 트리를 만들고 **위가 바깥 함수, 아래가 안쪽 함수**(뿌리가 위)로 그린다. 한 줄 높이는 18px이고, 폭은 표본 비율이다.
  - 폭이 좁으면 글자를 줄이거나 생략한다. 2px보다 좁은 칸은 그리지 않는다.
  - 마우스를 올리면 함수 이름·표본 수·전체 대비 % 말풍선을 띄운다.
  - 누르면 그 함수를 전체 폭으로 확대하고, 다시 누르거나 뿌리를 누르면 돌아온다.
  - 색은 함수 이름 해시로 따뜻한 계열 몇 단계 중 하나를 고른다(상태 색은 쓰지 않음). `highlight` 함수는 테두리로 강조한다.
  - 빈 스택이면 "이 구간에 수집된 표본이 없습니다"를 보인다.
- `compareLeaf(stacksA, stacksB)` → `[{leaf, pctA, pctB, diff}]`, `diff` 내림차순. leaf는 마지막 `;` 뒤다.
- `verdict(cmp)` → 비중이 가장 크게 는 함수 한 줄, 예: "호가 등록 함수 `book_insert` 비중 **15% → 63%**". 함수 설명 사전은 두지 않고 이름만 쓴다.
- `renderTopTable(el, stacks)`: leaf별 상위 10개 표. 03 §2 축소 순서 4번용이다.
- `#dev/flame`: mock의 A·B 프로파일을 나란히 그린다(D5 전에 혼자 확인하는 화면).

### 테스트
- **권장(자동):** `compareLeaf`를 순수 함수로 두고, `#dev/flame?selftest=1`이 고정 입력의 기대값을 콘솔에 `PASS`·`FAIL`로 찍는다.
- **수동:** mock B에서 `book_insert` 칸이 가장 넓다. 확대·복귀가 된다. 말풍선 %의 합이 맞다.

### 완료 기준
위 확인. `#dev/flame`에서 verdict가 "`book_insert` 15% → 63%" 근처로 나옴.

## D4. 대시보드: 열지도 · 이상 서버 · 업무 패널 · 배치판 진행, 서버 목록 [하]

| 항목 | 내용 |
|---|---|
| 세션 · 시각 | 세션 4 · 12:15–13:15 |
| 선행 | D1 |
| 마일스톤 | **M2** |
| 쓰는 경로 | `static/dash.js`(D1 임시 차트 교체), `static/pages.js`의 `#hosts` 부분 |
| 읽을 것 | 02 §6(`/hosts`, `/series`, `/panels`, `/flows`), §12.1, 기획서 8쪽 시안 |

### 만들 것 (`#dashboard`, 2초 갱신, 트리 범위 `?g=`로 거름)
1. **서버 열지도**
   - 그룹마다 한 줄이고 그룹 이름과 대수를 단다. 칸 하나가 서버 하나(약 18×18px, 2px 간격)다.
   - 정상 칸은 CPU 구간(0–25, 25–45, 45–60, 60–70)을 한 색의 진하기 4단계로 칠한다.
   - warn·crit·silent 칸은 상태 색과 기호(`!`, `✕`, `–`)로 표시한다.
   - 마우스를 올리면 서버·그룹·CPU·메모리·상태, 누르면 `#host/<id>`.
   - 아래에 범례(진하기 4단계 + 상태 3개)를 둔다. 폭 1280에서 서버 43대가 스크롤 없이 들어간다.
2. **이상 서버 목록**
   - 심한 순(crit, silent, warn)으로 서버, 그룹, 이유(`reasons`), 값을 보인다.
   - 최근 15분 CPU 꺾은선은 `/series?host=<id>&name=host.cpu.pct&step=30`이고, 작은 SVG 선이면 충분하다.
   - 마지막 줄은 `N대 정상`이다.
3. **업무 패널**
   - `/panels`에서 범위 안 그룹의 패널을 고른다. 범위가 없으면 전부다.
   - 타일은 제목, 값(천 단위 쉼표) + 단위, 상태(색 + 글자 "주의"·"위험")다. 값이 `null`이면 "서비스 미기동"이다.
   - 타일을 누르면 `#run/<exec_id>`로 간다. 기획서 8쪽처럼 `p99 응답` 타일에 "누르면 타임머신 →" 안내를 단다.
4. **배치판 진행**
   - `/flows`로 배치판마다 오늘 플로우의 상태 비율 막대를 그린다(완료·실행 중·예정·조건 대기·실패, 칸 사이 2px 간격, 범례).
   - 실패한 플로우는 따로 한 줄로 쓴다(`대외송수신 › ext-send-margin  10:12 종료 코드 2 · 재시도 2회 모두 실패  실행 기록 →`).
5. **서버 목록** `#hosts`: 표(상태, 서버, 그룹, CPU, 메모리, load1, 마지막 수신). 심한 순이고 범위로 거른다.

### 테스트 (미룸 가능 → 수동 확인)

   - 시작은 `started_at − 5분`이다.
   - 끝은 `ended_at + 5분`이다. 실행 중이거나 `procs > 0`이면 지금이고, 이때는 2초마다 오른쪽으로 민다. 사용자가 구간을 고른 뒤에는 밀지 않는다.
3. **띠 차트 5개**: uPlot 5개를 위아래로 쌓고 `cursor.sync`로 커서와 선택을 묶는다. 시간축은 맨 아래 띠에만 숫자를 단다.

   | 띠 | 요청 | 계열 | 단위 |
   |---|---|---|---|
   | 처리량 | `/series?exec_id=&name=biz.order.*` | 접수(점선), 처리 | 건/초 |
   | 처리 대기 | (같은 응답) | `biz.order.queue` | 건 |

   | 서비스 CPU | `/series?exec_id=&name=job.cpu.pct` | 그 실행 | % (코어 1개 = 100) |
   | 서버 CPU | `/series?host=<run.host>&name=host.cpu.pct` | 서버 | % (전체 = 100) |

   - `biz.*`가 없는 실행(배치 스텝)은 앞 3개를 숨긴다.

4. **A·B 구간 고르기**

   - 축소 순서 3번 대비로 `고정 구간` 버튼을 둔다. 누르면 A = 화면 앞 30초, B = 화면 마지막 30초다.
5. **플레임 그래프 A·B**(D3)
   - 차트 아래에 나란히 둔다. 머리는 `A 평시 10:41:10–10:41:40 · 표본 441` 꼴이다.

   - 구간을 하나만 골랐으면 그 하나만 그린다. 아무것도 안 골랐으면 화면 전체 구간 1개를 그린다.
6. **요약**: 종료 코드, 소요, peak CPU·RSS, attempt, 실행 방식, 상태 전이(`events`) 한 줄씩, 로그 끝 200줄(`<pre>`, 접기).
