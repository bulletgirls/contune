# 07. 사용자 보드 — 관제는 그대로, 보드는 그 옆에 (2026-11-11)

> 질문: "그라파나처럼 사용자가 패널을 유동적으로 구성하게 하면 관제·업무 대시보드까지 대체할 수 있지 않나?"
> 결론(사용자 결정, 11-11): **관제 화면은 고정으로 두고, 사용자가 구성하는 보드를 따로 제공한다.** 범용 그라파나를 다시 만들지 않고,
> 이음만 아는 개체(배치·실행·서비스·이벤트·위험도)를 지표와 한 보드에 섞을 수 있게 하는 데 집중한다. 구현은 카드 [W](cards/W-boards.md).

## 1. 왜 "대체"가 아니라 "옆에"인가

| 근거 | 내용 |
|---|---|
| 업계가 둘을 같이 둔다 | Grafana는 자기 앱(쿠버네티스 모니터링 등)을 대시보드가 아니라 Scenes로 만든다(드릴다운·앱 흐름). Datadog은 기본 대시보드를 복제해 고치게 하고, Kibana는 고정 화면 안에 대시보드를 끼운다. Stonebranch는 홈 대시보드를 편집 불가·복사만, Control-M은 정해진 위젯 목록 + 범위(viewpoint)로 누르면 그 잡 목록 |
| 관제는 쿼리가 아니다 | 위험도(요인·용인), 서버 고리, 금일 배치, 시간대별 배치(누르면 그 실행의 플로우 그래프), 확인 표시가 있는 이벤트는 여러 개체를 합친 도메인 객체다. 빌더가 더해 주는 것은 배치의 자유뿐이고, 05 §14.2 원칙(같은 사실 한 번, 이상은 한 목록)은 빌더로 지킬 수 없다 |
| 데이터 모델 | 계열의 축은 `host · name · exec_id(주인 키)` 셋. 임의 라벨·쿼리 언어·플러그인 생태계로 그라파나와 겨룰 수 없다 |
| 무덤 | Grafana 모범 사례의 낮은 성숙도 = 모두가 편집, 복사본, 일회성 대시보드가 영원히 남음. 높은 성숙도 = 승인된 대시보드, 브라우저 편집 없음, 파일로 관리 |

## 2. 결정

| # | 결정 | 이유 |
|---|---|---|
| 1 | 보드 하나 = `dashboards/<id>.yaml` 하나. **파일이 기준**이고 화면 편집기는 그 파일을 쓴다(플로우 편집기와 같음) | 깃으로 관리·검토(Grafana Git Sync·Perses와 같은 방향). 사람이 파일을 고쳐도 바로 보인다 |
| 2 | **보드는 알림을 내지 않는다.** 위젯 기준(warn·crit…)은 색과 기준선만. 알림은 업무 패널 타일의 몫이고, 위젯이 그 판정을 그대로 보이려면 `ref: {panel, tile}` | Grafana도 알림을 패널에서 떼어 냈다. 보드를 만들거나 지워도 알림이 따라 생기거나 사라지지 않는다 |
| 3 | 저장·삭제는 **운영 이상**, 감사 기록(`dash.save`·`dash.delete`), rev(파일 sha)로 동시 편집 충돌 409. 설정 `dashboards_readonly`로 화면 편집을 끈다 | 명령을 실행하지 않는 보기 정의라 관리까지 올리지 않는다. 대신 누가 언제 바꿨는지 남긴다 |
| 4 | 위젯 14종 = **지표 5**(값·시계열·막대·표·글) + **운영 9**(업무 지표·실시간 이벤트·서버·서버 맵·금일 배치·시간대별 배치·장애 위험도·로그·서비스) | 사용 통계상 시계열·값·표가 대부분(한 조직 그라파나 3,000개: timeseries 16,045 · stat 7,007 · table 2,630). 운영 위젯은 관제의 렌더러를 그대로 쓴다 |
| 5 | 쿼리 = 지표(이름·접두사) + 범위(그룹·서버·서비스) + 합치기(avg·sum·max·min) + 나눠 보기(하나로·서버마다·주인마다) + 값 하나(마지막·평균·최대·최소). 수식(a/b)은 뒤로 | Datadog·Zabbix·Grafana 빌더의 공통 최소(지표·필터·그룹 집계·시간 묶음). 지금 `/series`가 거의 다 가졌다 |
| 6 | 지표 위젯 값은 **매니저가 보드 단위로 한 번에** 계산한다(`GET /dashboards/{id}/data`). 운영 위젯은 보드마다 공용 응답을 한 번씩 가져와 나눠 쓴다 | 위젯마다 요청하면 2~5초 갱신 × 위젯 수 × SQLite. 그라파나도 위젯 수가 성능 문제의 첫 원인이다 |
| 7 | 배치는 12칸 격자에 순서대로(폭 1~12칸, 높이 1~8줄). 편집은 끌어서 순서 바꾸기 + 폭·높이 고르기. 자유 좌표·크기 끌기는 하지 않는다 | 빌드 단계 없는 vanilla JS로 단단하게. Datadog도 자유 캔버스(Screenboard)를 격자로 합쳤다 |
| 8 | 새 보드는 **템플릿**에서 시작: 빈 보드 · `ops`(관제와 같은 구성) · `panel:<id>`(업무 패널의 타일·차트·로그) | "관제를 고치고 싶다"는 요구는 관제를 복제한 보드로 푼다. 관제 자체는 바뀌지 않는다 |
| 9 | 범위 우선순위: 위젯 scope > 보드 group > 트리에서 고른 그룹 | 정산팀 보드는 트리를 바꿔도 정산을 본다. 범위를 안 정한 보드만 트리를 따른다 |
| 10 | 벽면 표시: `#dash/<id>?tv=1`(위 막대·트리 숨김, 큰 글자). 보드 순환은 뒤로 | 관제 벽면 대체의 최소. Grafana 키오스크·Datadog TV 모드와 같은 자리 |
| 11 | 보드는 **보기 머리의 고르기 칸**에서 고른다(목록 화면 없음). `#dashes`는 마지막에 본 보드(없으면 첫 보드)로 가고, 고르기 칸으로 바꾸면 화면을 다시 그리지 않고 보드 칸만 갈아 그린다. 주소는 `#dash/<id>`로 바뀌어 뒤로 가기·즐겨찾기는 그대로. 고정 구간·트리 그룹은 이어 가고 실시간 구간은 새 보드의 기본 구간. 설명·마지막 저장은 ⓘ, 읽지 못한 파일은 ⚠(운영 이상), 새 보드는 고르기 칸 맨 아래 | 관제하는 사람은 보드 한두 개를 번갈아 보는데, 목록을 거치면 매번 화면이 바뀐다(11-11 사용자 제안). Grafana도 대시보드 제목 자리에서 바로 다른 대시보드로 간다. 보드가 수십 개로 늘면 고르기 칸에 검색을 붙인다 |

하지 않는 것: 수식, 위젯별 구간, 보드 변수(드롭다운), 개인 보드·폴더·권한 나누기, 보드 순환(플레이리스트), 버전 이력 화면(파일·감사 기록으로 대신), 외부 데이터 소스.

## 3. 모양

```yaml
# dashboards/trading.yaml
id: trading
title: 매매 현황
range: 1h
group: 매매
widgets:
  - { id: queue, type: stat, ref: { panel: matching, tile: 대기 큐 } }          # 패널 타일 그대로(알림도 패널 것)
  - { id: tps, type: timeseries, title: 처리량, w: 6, h: 2, scope: { service: matching },
      queries: [ { metric: biz.order.in_tps, agg: sum, label: 유입 }, { metric: biz.order.tps, agg: sum, label: 체결 } ] }
  - { id: cpu, type: bar, title: 서버별 CPU, queries: [ { metric: host.cpu.pct, by: host } ], unit: "%", warn: 70, crit: 90, top: 10 }
  - { id: ev, type: events, w: 4, h: 4 }
  - { id: bat, type: batch, scope: { board: 정산 } }
```

모델은 `internal/model/dash.go`, API는 `internal/manager/dash/dash.go` 머리말, 화면 계약은 `web/static/widgets/index.js` 머리말이 기준이다.

## 4. 결과

진행: 계약 W0(모델·`dash` 패키지 자리·주인 키 접두사 조회·조립·화면 라우트·위젯 등록부)을 먼저 커밋하고, 쓰는 경로가 겹치지 않는 7레인을 두 물결로 돌렸다.
물결 1: W-A(보드 파일·검증·CRUD·감사·템플릿·예시 보드) · W-B(`/data`·미리보기·지표 목록) · W-D(지표 위젯) · W-F(mock) · W-G(운영 위젯).
물결 2(물결 1 병합 위): W-C(목록·보기·격자·갱신·벽면, `mountBoard`) · W-E(편집기). 레인 보고는 10줄 이내로 받고, 레인 사이에 걸친 것만 오케스트레이터가 고쳤다.

| 확인 | 결과 |
|---|---|
| Go | `gofmt`·`go vet`·`go test ./...` 통과. 새 테스트: 검증 표 약 70사례, Book·CRUD·감사·409, 템플릿, 값 계산(by·agg·reduce·상태·Ref·접두사·서비스 범위·top·실행 이름), 지표 목록, live 이름, 저장소 주인 키 접두사 |
| 실제 매니저(18390, `demo.sh setup·up·run·quote·surge`) | 예시 보드 셋이 그려짐. 체결·시세 Ref 타일·시계열·서버별 CPU 막대(상위 10)·서비스 자원 표(by owner) 값이 참. 폭주 중 운영 벽면이 위험도 100·이벤트를 관제와 같은 모양으로. 콘솔 오류는 로그인 전 401 하나 |
| 편집기 | 템플릿(ops·panel:matching) → 위젯 더하기 → 지표 고르기 → 끌어서 순서·앞으로/뒤로 → 저장 → 보기, 기존 보드 고치기·409 다시 불러오기·삭제·조회 역할·편집 꺼짐·틀린 파일 안내. mock·실제 둘 다 |
| 화면 | 밝음·어두움, 390px 좁은 폭, 벽면 `?tv=1`(Esc로 나감), mock의 틀린 파일 `night`(목록 경고·조회 422). 결정 11(고르기 칸) 뒤 mock에서 고르기·구간 이어 가기·뒤로 가기·메뉴·벽면 드나들기·새 보드·`night`(⚠·조회 422)을 다시 확인, 콘솔 오류 0 |

레인이 정한 것(카드에 없던 것):
- W-A: `model.WidgetIDOK`, `dash.ErrInvalid`(저장 검증 실패 400, 틀린 파일 조회 422). rev를 줬는데 파일이 없으면 409(지금 rev `""`).
- W-B: 접두사 쿼리에 label이 있으면 `label · 펼친 이름`. table은 접두사 쿼리를 그 agg로 한 칸에 합침. POST 본문의 모르는 칸은 받아 준다.
- W-C: 구간은 지표 위젯과 로그만 따른다(운영 위젯은 늘 지금). 미리보기에서 서버가 400으로 거절한 정의는 다시 보내지 않는다. 핸들에 `range()`·`opts.onRange`.
- W-D: 시계열 이름표는 공통 앞부분을 빼고 한 줄, 넘치면 `외 N개`. 값 단위 환산(KB → GB). 좁은 막대 칸은 막대를 아래 줄로.
- W-E: 지표 위젯에도 범위(그룹·서비스) 칸, stat은 나눠 보기 숨김, 편집기에서는 트리를 숨기고 Esc로 선택 해제. 미리보기에서 지표가 빈 위젯은 W-C가 그 틀에 `지표 없음`으로 보인다.
- W-G: 업무 지표 타일 수는 실제 크기를 재서 맞춘다(위험·경고 먼저). limit 기본 events 30 · logs 50 · services 30.
- 오케스트레이터: 카탈로그 이름에서 차트 제목과 항목 제목이 같으면 한 번만, 감사 기록 분류에 보드, mock `/logs` 주인 키 접두사, 서비스 위젯 needs에 hosts, Ref 값 위젯 제목 = 타일 제목, 관제 구성의 서버 맵 3줄·이벤트 5줄.

남은 것: 수식(a/b)·보드 변수·보드 순환·버전 이력 화면은 하지 않았다(§2). `live.Names()`는 아직 정리되지 않은 10분 넘은 키도 live로 셀 수 있다. 브라우저 뒤로 가기는 편집기의 저장 안 한 변경 확인 없이 나간다. 아주 좁은 칸(폭 2)에서는 긴 숫자가 말줄임된다.
