# contune (Con-A-Tune)

배치 스케줄러, 서버 관제, 업무 지표 수집, **함수 단위 추적**을 한 제품으로 새로 만든 **경량 스케줄러·관제 통합 도구**입니다. 비싸고 거대한 상용 제품 없이, 운영에 실제로 쓰는 기능과 **데이터 주권**을 함께 갖는 것이 목표입니다.

핵심 아이디어: **스케줄러가 실행마다 실행 ID(`exec_id`)를 발급하고, 그 실행과 실행이 띄운 서비스 프로세스의 자원, CPU를 쓴 함수, 같은 시각의 서버 지표와 업무 지표를 같은 키와 같은 시간축으로 우리 DB에 쌓습니다.** 주문이 몰려 체결이 밀리면 업무 지표에서 그 서비스를 띄운 실행으로 바로 가고, 타임머신에서 밀린 구간을 골라 CPU를 쓴 함수까지 내려갑니다. 같은 데이터는 SQL과 CSV로 꺼내 통계나 머신러닝에 씁니다.

## 결정 사항 (2026-10-27)

| 항목 | 결정 |
|---|---|
| 언어 | Go (단일 바이너리: `manager`, `agent`, `dev`, `burn`, `sql`). 시연용 체결 서비스만 운영 환경과 같은 C |
| 해커톤 | 하루, 2명. 코드는 당일 처음부터 작성(대회 규칙). 사전에는 설계 문서, 작업카드, AI 지시문만 준비 |
| 심사 | 서류: 창의성 30, 업무 도구 실용성 30, 구현 가능성 20, 기대 효과 20 |
| 산출물 | 새 스케줄러의 **개념 검증판**. 15:00까지 개념 7개(스케줄, 원격 실행, 한 통로 수집, 실행 ID 연결, 함수 단위 추적, 데이터 주권, 보안 최소선)를 최소 형태로 잇고 이후에는 넓히기만 함. 기존 도구 연결이나 단계적 이행 계획은 두지 않음 |
| 함수 단위 추적 | Linux `perf`로 스크립트가 띄운 C 서비스 프로세스까지 실행 ID로 상시 표본 수집(초당 49회, 10초 구간), 플레임 그래프. 실측: 프로파일러 CPU 약 0.6% |
| 플로우 그래프 | 갈래·합류·서버 넘기를 그리는 DAG 화면(핵심) |
| 데이터 주권 | 공개 스키마, 분석용 뷰 `v_samples`·`v_profiles`, `contune sql`(읽기 전용), CSV·접힌 스택 내보내기 |
| AI | 제품 기능이 아니라 개발 수단(사람 1명당 AI 세션 2개) |
| 운영 환경 | 업무는 온라인(체결) 중심, 배치는 개장 준비와 정산. 배치는 셸 스크립트, 스크립트가 띄우는 서비스는 C(자바 일부). 운영 서버는 perf 사용 가능 |
| 업무 지표 | 접수·처리 건수, 대기 건수, 응답시간을 시스템 지표와 같은 통로로 |
| 시연 | Docker Compose: 매니저 1 + 에이전트 3. 장애 장면은 주문량 폭주로 체결 처리가 밀리는 상황. 체결 서비스는 합성 주문으로 부하를 만드는 시연용 C 프로그램, 서버 자원은 시뮬레이터 |
