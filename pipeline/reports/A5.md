다음 카드에 알릴 것:
- perf 설정: profiler: {type: perf, hz: 49, call_graph: dwarf|fp|none, perf: "perf", tmp_dir: ""}. 잘못된 call_graph·hz면 Build 에러(dev.go는 이때 프로파일러 없이 띄움). perf 실행 파일이 없어도 Build는 성공하고 Profile마다 에러 → agent.profiler.errors.
- Loop: 구간 하나는 실제 시간으로 최소 Window(프로파일이 일찍 실패해도 바쁜 반복 없음). Profile.TS = 구간 시작(o.Now), agent.profiler.* 지표 TS = 구간 끝, Host 채움, ExecID 없음. 스택이 비면 AddProfile 안 함. ctx 취소로 끝난 Profile은 실패로 세지 않고 지표도 안 냄.
- cpu_pct = perf record + perf script의 rusage(utime+stime) 합 ÷ Window × 100(코어 1개 = 100). 실패한 시도의 CPU도 더한다.
- perf record는 출력 파일이 있으면 .old로 옮기므로 tmp와 tmp.old 둘 다 defer로 지운다.
- `go test`(‑c 없이)는 테스트 바이너리 심볼을 지워 perf가 [unknown]만 보인다. TestPerfReal은 심볼이 없으면 `go test -c`로 따로 빌드해 자식으로 쓴다.
