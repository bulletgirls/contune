다음 카드에 알릴 것:
- A3: `Start(cmd, StartOptions{LogDir, WorkDir, Host, Vars, KillGrace, Now})`가 에러면 아직 아무 프로세스도 뜨지 않은 것이다(빈 명령, 잘못된 exec_id, LogDir 비어 있음, `${NAME}` 미정의, 실행 파일 없음, 폴더·로그 파일 생성 실패) → exit 127로 보고하면 된다.
- A3: 성공하면 `Job.PID()`(= pgid)를 바로 추적기에 등록하고, `Job.Wait()`는 리더가 끝나고(시간 초과·Kill이면 그룹 종료 절차까지 끝난 뒤) 한 번만 정해지는 `Result{Status SUCCEEDED|FAILED|TIMEOUT|KILLED, ExitCode(신호면 128+n), LogTail(끝 64KB 안 200줄), StartedAt, EndedAt(unix ms, Now 기준)}`을 몇 번이고 돌려준다.
- A3/A6: `Job.Kill(reason)`은 고루틴 안전하고 멱등이다. 이미 끝났거나 시간 초과 절차가 먼저 시작됐으면 아무것도 하지 않으며(상태는 먼저 정해진 것), 그룹에 SIGTERM → KillGrace(기본 5s) 안에 그룹이 비지 않으면 SIGKILL. setsid로 빠진 서비스는 건드리지 않는다.
- 로그 파일은 `<LogDir 절대 경로>/<exec_id>.log`(APPEND)라 같은 exec_id로 다시 띄우면 이어 쓴다. stdin은 /dev/null, stdout·stderr는 같은 파일(파이프 없음).
- 자식 환경 우선순위: os.Environ() < vars < EUM_*(EUM_EXEC_ID·FLOW·STEP·HOST·PROFILE(1/0)·LOG_DIR). PATH = `<os.Executable() 폴더>:<vars의 PATH 또는 에이전트 PATH>`, 실행 파일 찾기도 이 PATH로 한다. `/`가 든 상대 경로는 WorkDir 기준.
- 시간 초과는 `Command.TimeoutSec`(초, 0이면 없음)로 Job 안에서 잰다(실시간 타이머, Now는 결과 시각에만 씀).
- 이 파일들은 `//go:build linux`의 `setGroup`·`terminateGroup`·`exitCode`에 기대므로 패키지 `exec`는 리눅스에서만 빌드된다(쓰는 경로 밖이라 다른 OS용 파일은 만들지 않음).
계약 변경: 더한 것만 — `(*Job).Kill(reason string)` 메서드(카드의 "넘겨주는 것"), `Job`의 내부 필드. 시그니처 변경 없음.
