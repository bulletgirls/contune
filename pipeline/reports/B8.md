다음 카드에 알릴 것:
- 응답의 "flow"는 YAML 키 JSON: {id, board, schedule, on_missed, steps:[{id, host, command, depends, timeout, retry:{count,interval}, profile, gate, gate_max_wait, level}]}. 기간은 "10m"·"1h" 문자열, 0이면 "". 슬라이스는 null이 아니라 []. 이 모양을 그대로 PUT·validate의 "flow"에 넣어도 된다(왕복 확인함, board·level 같은 남는 키는 무시).
- 입력 "flow"는 JSON → YAML로 옮긴 뒤 flowdef.Parse를 지난다. "yaml"(원문)도 validate·PUT 모두 받지만 저장은 항상 Parse → 검사 → Marshal 결과다(원문을 그대로 쓰지 않음).
- 배치판: 본문 "board" → 없으면 flow 객체의 "board" → 없으면 기존 플로우의 배치판 → 없으면 ""(flows 바로 아래).
- if_match는 그 id의 기존 파일(레지스트리의 File, 없으면 대상 경로에 파일이 있을 때)의 sha와 비교. 새 플로우면 무시.
- CheckFlow 에러 줄은 `스텝 <id>: 허용되지 않은 명령: <문자열>`. 허용 목록 정규식이 틀리면 모든 검사에 `허용 목록 오류: …`가 붙고 examples는 [].
- 검증 실패 400 본문은 {"error":"검증 실패","errors":[…]}, 저장 뒤 Reload 실패 500 본문은 {"error":…,"errors":[…]}.
- 감사 detail: 저장 `<file> <old sha|-> → <new sha>`, 배치판 이동이면 `<옛 file> → <새 file> <old sha> → <new sha>`, 삭제 `<file> <sha> → -`. actor `user:web(<주소>)`.
- 저장·삭제는 편집기 안 뮤텍스로 한 번에 하나씩. 임시 파일은 같은 폴더의 `.eum-edit-*.tmp`(로더가 읽지 않는 확장자).
- B9: validate 로직은 handler 내부(check)라 패키지 밖에서 부를 수 없다. 초안 검증은 POST /api/v1/flows/validate와 같은 순서(flowdef.Parse → flowdef.Validate → editor.Compile·CheckFlow)로 직접 조합하면 된다.
