[완료] E1 시연용 체결 서비스 matching_svc
변경: demo/matching_svc.c, demo/build.sh, demo/README.md
테스트: go test ./... 통과(테스트 파일 없음). 카드의 수동 확인 1,2,3,5 수행, 4(perf)는 이 PC가 perf_event_paranoid=4라 건너뜀
완료 기준:
- 1 빌드: gcc 9.4 -O2 -Wall -Wextra 경고 없음. 심볼 book_insert 등 그대로(noinline+noipa라 .isra 접미사 없음), 꼬리 호출 없음 확인(objdump)
- 2 평시 1500건/초: CPU 약 25~27%(/proc 5초 구간), queue 0, avg 0.2ms, p99 0.5~2ms, 이력 0%, (I) START 한 줄, 호가 깊이 약 260/500
- 3 폭주 6000건/초(약 20초 후): CPU 100%, 처리 약 5,900건/초, queue 2,100~2,600 증가 중, avg·p99 390~440ms, 이력 24~26%(통보 5,000/초 초과분만 오름, 90%까지는 수 분), (W)는 약 8초 뒤부터, (E) QUEUE·LATENCY는 약 15~20초 뒤부터 각 5초에 한 줄. 1500으로 되돌리면 20초 안에 queue 0으로 회복하고 (E) 멈춤
- 5 push: 한 데이터그램 6줄 `name value exec_id` 형식 확인(EUM_EXEC_ID 있을 때)
수동 확인 항목: perf로 book_insert 비중 비교(perf 되는 PC에서)
다음 카드에 알릴 것:
- push 지표 6개: biz.order.{in_tps,tps,queue,latency_avg_ms,latency_p99_ms,histbuf_pct}
- 튜닝 상수: COST_RISK=21600, COST_CROSS=14000, COST_EXPIRE=400000, COST_SCAN=23, PASSIVE 0.04→0.70(1500→6000건), EXPIRE_SEC=10, HIST_CAP=200000, 통보 5000/초. 절대값은 CPU 속도에 의존
- 카드와 다른 점: expire_orders는 1초가 아니라 100ms마다 호출(1초 한 번이면 약 30ms 정지로 평시 p99가 튐). 함수 비중은 perf 없이 반복 횟수 비율로만 맞췄고 실측은 못 함
- 이력 버퍼 사용률은 6000건에서 초당 약 +0.5~1%p로 천천히 오른다. HISTBUF (E)는 오래 두어야 나온다(필요하면 HIST_DRAIN_PS를 낮춘다)
- 로그 분류는 QUEUE, LATENCY, HISTBUF, RATE, START, STOP. SIGTERM·SIGINT 모두 STOP 후 종료
계약 변경: 없음
